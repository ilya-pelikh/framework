# Настройка хоста, выпуск и откат релизов

Функция `createHost` принимает путь к реестру, разрешённые origin, таблицу маршрутов
и слотов, URL загрузчика островов, рендерер оболочки, а также необязательные лимиты
и обработчик диагностических событий. Слот задаёт `name`, `moduleId`, `props`
(JSON или функцию от запроса) и доверенный HTML для отображения при ошибке.
Оболочка получает соответствие имён слотов готовым HTML-фрагментам.
Оболочка не гидратируется. Неизвестный маршрут возвращает 404, ошибка оболочки — 500;
при отказе отдельного слота сохраняется статус 200. Ответы страниц используют `no-store`.

```json
{
  "catalog": {
    "releaseId": "v1",
    "manifestUrl": "http://localhost:4101/releases/v1/manifest.json"
  }
}
```

Origin каждого URL должен входить в `allowedOrigins`. Перенаправления запрещены.
До запроса рендеринга хост проверяет origin всех ресурсов манифеста;
пользовательские props не могут задавать адрес обращения к сервису.
Параметр `limits` поддерживает `timeoutMs` (1500 мс), `manifestBytes` (65536 байт)
и `renderBytes` (1048576 байт). Общий срок ожидания охватывает получение манифеста
и рендеринг. При отключении клиента незавершённые запросы отменяются.
Слоты обрабатываются параллельно.

Функция `context(request)` может выбирать серверные данные для передачи модулю.
Пересылаются только ключи из `allowedContextKeys`, за исключением ключей cookies
и авторизации. Не помещайте секреты в разрешённые поля. Заголовки запроса не копируются.
Обработчик `onDiagnostic` получает `requestId`, `moduleId`, `releaseId`, `slot`
и `role`/`stage`/`category`/`durationMs`, но не исходные исключения или props.
`onMetric` использует только bounded role/stage/outcome labels. Correlation,
immutable manifest cache, admission defaults и API настройки: `operations.md`.

Порядок выпуска и отката:

Полная процедура probes/rollout/drain, расчёт retention и manual cleanup:
`rollout-retention.md`. Старые assets нельзя удалять сразу после registry switch.

Перед включением strict loader мигрируйте прежние релизы по `release-migration.md`.
Требуются полный inventory доверенного CI/build snapshot и закреплённый digest;
перечень оставшихся deploy files не заменяет это свидетельство.

1. Соберите релиз с новым уникальным идентификатором и опубликуйте его каталог рядом с предыдущим.
2. Запустите модуль с определениями обоих релизов. До изменения реестра проверьте
   готовность сервиса, манифест, ответ рендеринга и браузерные ресурсы.
3. Запишите полный новый реестр во временный файл рядом с действующим, затем
   замените действующий файл переименованием в пределах одной файловой системы.
   Не редактируйте действующий JSON непосредственно.
4. Следующие запросы хоста используют новый снимок реестра без перезапуска.
   Уже выполняющиеся запросы сохраняют прежний снимок. При некорректном обновлении
   используется последняя корректная конфигурация.
5. Для отката атомарно замените реестр предыдущей версией.
   Сохраняйте старые адреса рендеринга и ресурсы для уже открытых страниц.

Тест `tests/host.test.ts` выполняет переключение v1 → v2 → v1 без перезапуска хоста,
в том числе во время ожидания манифеста текущим запросом.
Запустите `npm test`, чтобы повторить этот сценарий.
Проверка готовности возвращает 503, если нет исходного корректного реестра
или обязательных локальных файлов. Недоступность удалённых модулей на неё не влияет.

## Контракт оболочки

Каждый переданный slot-string включает служебные comment boundaries. Вставляйте
его ровно один раз, целиком, без разбора, экранирования, удаления или дублирования
markers. Shell вызывается один раз. После HTML parsing хост проверяет принадлежность
узлов, живые wrappers и уникальность всех ID. Shell/framework имеет приоритет перед
слотами; между слотами выигрывает первый в конфигурации, независимо от DOM-порядка.
Отклонённый слот заменяется fallback, его descriptors/CSS не включаются в страницу.

Fallback — статический доверенный HTML без scripts, reserved namespace и islands.
Он обязан быть корректным в том же HTML-контексте (например, явный `tbody` в таблице).
Перепроверка ограничена числом слотов плюс один. Некорректный shell/fallback или
неатрибутируемый parser repair возвращает безопасный 500, а не повторный shell вызов.
Регрессии: `tests/composition.test.ts`, `tests/composition.e2e.ts`.

## Private service boundary

`HostOptions.serviceCredentials` принимает `new ServiceCredentials(originToToken)`.
Это service-owned credentials только для exact manifest/render origin/path, не
Authorization/Cookie входящего пользователя. `createModuleService({serviceTokens})`
закрывает private endpoints до body parsing; GET/HEAD versioned assets публичны.
Target profile, proxy/permissions и secret rotation: `deployment-profile.md`.

## Production browser policy

`productionHeaders(moduleOrigins)` подключается до static/routes собственного
Express app. Standalone host включает его из target deployment profile.
Shell использует `/assets/shell.css`; JSON payload остаётся inert data block.
Не добавляйте inline scripts/styles для production. Политика, HTTPS proxy и
воспроизводимая browser проверка: `browser-security.md`.
