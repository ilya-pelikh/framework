# Жизненный цикл островов в браузере

Импортируйте `bootstrap` и `dispose` из `@islands/client`.
Загрузчик островов не зависит от React. Он читает данные из `#islands-payload`
либо принимает дескрипторы напрямую. Браузерная точка входа каждого модуля
экспортирует `hydrate`, полученный через `createIslandEntry(Component)`
из `@islands/client/react`.
Компоненты получают `{data: props}` и на сервере, и в браузере.
Используйте `useHydrated()`, чтобы включить элементы управления после первого
рендера, совпадающего с серверной разметкой.
Функция `useId()` используется обычным образом: рендерер передаёт один и тот же
уникальный `identifierPrefix` в SSR и `hydrateRoot`.
Между корневыми React-деревьями нет общего контекста или состояния приложения.

Политики гидратации:

- `load`: импорт запускается при выполнении `bootstrap`.
- `visible`: при первом пересечении области просмотра; если API недоступен, применяется `load`.
- `idle`: используется `requestIdleCallback` с таймаутом 2000 мс; при отсутствии API — таймер на 200 мс.
- `never`: только SSR и CSS, без импорта и создания корневого React-дерева.

Импорты кешируются по URL, экземпляры отслеживаются по ID.
Повторный вызов `bootstrap` не сбрасывает состояние и не создаёт ещё одно корневое дерево.
Перед удалением контейнера вызывайте `dispose(id)`.
Чтобы освободить все экземпляры из переданного набора данных, вызовите функцию,
возвращённую `bootstrap`. Ожидающие наблюдатели и таймеры отменяются,
активные корневые деревья размонтируются. Завершившийся позже импорт не может
гидратировать освобождённый или удалённый из документа контейнер.
Идентификаторы освобождённых экземпляров повторно не используются.

При ошибке импорта сохраняется SSR-разметка и устанавливается `data-island-unavailable`.
При ошибке рендеринга локальная граница ошибок показывает резервное содержимое.
Обработчик `onError` получает `moduleId`, `releaseId`, `island` и категорию
(`import`, `render`, `mismatch`), но не props.
Восстановимые ошибки гидратации регистрируются диагностикой; браузерные тесты
успешных сценариев считают их провалом.
Не рассчитывайте на сохранение исходного DOM при ошибке внутри `hydrateRoot` или рендеринга.

До гидратации элементы управления отключены.
Повторное воспроизведение ранних событий и общий React-контекст между корневыми
деревьями не поддерживаются. Оболочка не получает корневого React-дерева.
Браузерный тест production-сборки проверяет эти API на реальных точках входа
каталога и корзины. После сборки приложений запустите:
`node --import tsx tests/production.e2e.ts`.

## Валидация и освобождение

Document payload — единственный `<script id="islands-payload" type="application/json">`
с массивом корректных descriptors. Ошибка всего payload сохраняет SSR и не создаёт
roots (`payload`). В явном массиве некорректная запись даёт `descriptor`, остальные
обрабатываются независимо. Runtime различает `missing-container`, `import`,
`entry-contract`, `hydrate` (синхронная ошибка entry) и `cleanup`. React adapter
дополнительно сообщает `render`/`mismatch`. Диагностика не передаёт props или сырые
исключения, а выброшенное исключение diagnostic sink не останавливает runtime.

`data-hydrated` означает успешную передачу управления entry, **не React commit**.
Включайте controls через `useHydrated()`, а не по этому атрибуту.
Состояния и ID-tombstones изолированы по `Document`; одинаковый ID в iframe независим.
Освобождение удаляет сильные ссылки на DOM, root и callbacks, но сохраняет ID до
конца жизни документа. Повторная гидратация освобождённого ID не поддерживается.

```ts
const releaseSet = bootstrap(descriptors, { onError: report })
dispose(descriptors[0].id)
releaseSet()
releaseSet()
bootstrap(descriptors)
```

Каждый cancel/unmount выполняется не более одного раза. Исключение одного cleanup
не мешает остальным. `dispose()` освобождает текущий document;
`dispose(id, frame.contentDocument)` — конкретный экземпляр другого документа.
Возвращённый disposer всегда относится только к созданному этим вызовом набору.
Проверки lifecycle, отмены pending import и detached DOM:
`node --import tsx --test tests/runtime-hardening.e2e.ts`.
