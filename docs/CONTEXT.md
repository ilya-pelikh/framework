## Цель и выполненная работа

Проект — расширяемый TypeScript-фреймворк серверной композиции React-страниц через
Express. Интерактивность включается отдельно для островов. Микрофронтенды имеют
независимые сборки, HTTP-сервисы и неизменяемые релизы.
Демонстрация включает каталог с фильтром и корзину с локальным счётчиком.

Работа началась с каталога, содержащего только OpenSpec и локальные навыки.
Созданы четыре пакета, три приложения, система сборки, проверки и документация.
Изменение `react-ssr-islands-microfrontends` использует схему `spec-driven`:
все **27/27 задач** отмечены выполненными, CLI подтвердил `all_done`.
Изменение **архивировано 2026-09-30** после синхронизации всех четырёх спецификаций.
Незавершённых задач в его списке нет; активных изменений OpenSpec после архивирования нет.

## Запуск и проверки

| Команда                                         | Назначение                                                          |
| ----------------------------------------------- | ------------------------------------------------------------------- |
| `npm ci`                                        | Установка зависимостей по lockfile                                  |
| `npm run dev`                                   | Сборка, запуск трёх приложений и полная перезагрузка при изменениях |
| `npm run build`                                 | Сборка приложений и production-launcher                             |
| `npm start`                                     | Запуск готового `dist/start.mjs`, без TypeScript-загрузчика         |
| `npm run typecheck`                             | Проверка типов корня и семи workspace-пакетов                       |
| `npm test`                                      | Тесты контрактов, HTTP, реестра, рендеринга и манифестов            |
| `npm run test:e2e`                              | Браузерные проверки production-сборок                               |
| `node --import tsx tests/start-smoke.ts`        | Запуск и остановка собранного launcher                              |
| `node --import tsx tests/dev-smoke.ts`          | Пересборка, автоматическая перезагрузка и остановка процессов       |
| `node --import tsx tests/deploy-release.e2e.ts` | Изолированное развёртывание и переключение каталога v1 → v2 → v1    |

Хост доступен на `http://localhost:4100`, каталог — на 4101, корзина — на 4102.
В режиме разработки порт 4103 обслуживает поток событий перезагрузки.
Для браузерных проверок нужен `npx playwright install chromium`.

Важные условия повторного запуска:

- Сборка без `RELEASE_ID` создаёт v1 и откажется перезаписывать существующий релиз.
  Даже после неудачной сборки нужен новый ID либо чистая копия проекта.
- В PowerShell новый релиз задаётся через `$env:RELEASE_ID='v2'`.
  Для отдельного каталога: `npm run build --workspace @islands/catalog`.
- Тест переключения релизов ожидает каталог v1 и v2, а корзину — v1.
- Сборка хоста заново записывает демонстрационный реестр с v1.
  Нужную конфигурацию развёртывания следует публиковать отдельно.
- Dev-сборки получают ID `dev-<timestamp>`. Старые релизы не удаляются автоматически.
- Сгенерированные `dist/`, `.cache/`, `node_modules/` не являются исходниками.
  Не следует полагаться на наличие временных результатов прошлой сессии.

## Подтверждённое состояние

В Windows и Ubuntu WSL прошли чистая установка, typecheck, 12 тестов,
production-сборки, браузерные E2E, отдельное развёртывание без исходников и
`node_modules`, переключение релизов, dev-reload и остановка дочерних процессов.
В успешных браузерных сценариях не было ошибок гидратации.
Подробности и размеры ресурсов сохранены в [acceptance.md](acceptance.md).

В `.github/workflows/ci.yml` настроена матрица Windows/Linux, включая проверки
production-launcher, браузера, релизов и разработки. Выполнены локальные проверки
обеих платформ; запуск на инфраструктуре GitHub Actions не отправлялся.

Особенности окружения, обнаруженные при проверках:

- Chromium в Ubuntu потребовал системные библиотеки; после их установки тесты прошли.
- `scripts/verify-linux.sh` создаёт изолированную копию и загружает нужную версию Node.
  `INSTALL_BROWSER_DEPS=1` явно включает установку системных зависимостей Chromium.
- Временные каталоги `/tmp/islands-verification.*` исчезали между сеансами WSL;
  их старые пути нельзя считать доступными при продолжении работы.
- Автоматические проверки остановки используют IPC-сообщение `stop`.
  В Windows проверка с открытым stdin-каналом зависала; вариант с IPC прошёл.
- Предупреждения Node-сборок об Express template loader и `supports-color`
  описаны в отчёте приёмки. Используемые сценарии работают из отдельных deploy-каталогов.
