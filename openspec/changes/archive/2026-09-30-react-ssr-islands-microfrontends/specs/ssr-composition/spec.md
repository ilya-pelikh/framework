# Spec Delta

## Purpose

Обеспечить готовую серверную страницу из независимых микрофронтендов с предсказуемыми отказами и изоляцией данных запросов.

## ADDED Requirements

### Requirement: Server composed document

Система SHALL возвращать полный HTML документа с содержимым настроенных слотов, стилями и данными островов без необходимости выполнять JavaScript для чтения начального содержимого.

#### Scenario: JavaScript disabled

- **WHEN** клиент запрашивает `/` с отключённым JavaScript
- **THEN** ответ 200 содержит каталог, начальное количество корзины и статическую оболочку с применимыми стилями

#### Scenario: Unknown route

- **WHEN** клиент запрашивает незарегистрированный маршрут
- **THEN** сервер возвращает страницу 404

#### Scenario: Shell failure

- **WHEN** невозможно сформировать оболочку документа
- **THEN** сервер возвращает 500 без stack trace и секретов

### Requirement: Bounded isolated fragment failures

Система SHALL ограничивать ожидание каждого слота настраиваемым deadline (1500 мс по умолчанию), отменять просроченные запросы и показывать fallback только отказавшего слота. Ответ manifest SHALL быть ограничен 64 KiB, render response — 1 MiB по умолчанию.

#### Scenario: Timeout or invalid response

- **WHEN** один сервис недоступен, превышает deadline/лимит, возвращает ошибку либо невалидный ответ
- **THEN** страница имеет статус 200, fallback этого слота и содержимое остальных успешных слотов; поздний ответ игнорируется

#### Scenario: Client disconnect

- **WHEN** клиент закрывает соединение до завершения композиции
- **THEN** незавершённые исходящие запросы отменяются

### Requirement: Request isolation

Система SHALL изолировать props и HTML разных запросов и передавать сервисам только разрешённый контекст. Диагностика SHALL идентифицировать запрос, слот, модуль и релиз без записи props или credentials.

#### Scenario: Concurrent differing props

- **WHEN** два одновременных запроса используют разные props
- **THEN** каждый документ содержит только свои props и SSR-данные, а cookies и authorization не пересылаются автоматически

### Requirement: Health and readiness

Система SHALL предоставлять `/healthz` для проверки процесса и `/readyz` для проверки локальной готовности.

#### Scenario: Remote unavailable

- **WHEN** локальная конфигурация корректна, но один удалённый модуль недоступен
- **THEN** readiness host остаётся успешной, а отказ модуля обрабатывается на уровне слота

#### Scenario: Invalid initial configuration

- **WHEN** при запуске нет корректного registry или обязательных локальных артефактов
- **THEN** readiness возвращает неуспешный статус
