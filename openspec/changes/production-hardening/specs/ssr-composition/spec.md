# Spec Delta

## MODIFIED Requirements

### Requirement: Server composed document

Система SHALL возвращать полный HTML документа с содержимым настроенных слотов, стилями и данными островов без необходимости выполнять JavaScript для чтения начального содержимого. Итоговый документ SHALL иметь уникальные DOM ID, один принадлежащий framework payload и однозначную принадлежность каждого live island-wrapper своему слоту. Namespace ID `islands-` и служебные composition markers SHALL быть зарезервированы framework; оболочка SHALL включать каждый настроенный слот ровно один раз без разрушения его границ.

#### Scenario: JavaScript disabled

- **WHEN** клиент запрашивает `/` с отключённым JavaScript
- **THEN** ответ 200 содержит каталог, начальное количество корзины и статическую оболочку с применимыми стилями

#### Scenario: Unknown route

- **WHEN** клиент запрашивает незарегистрированный маршрут
- **THEN** сервер возвращает страницу 404

#### Scenario: Shell failure

- **WHEN** невозможно сформировать оболочку документа, её собственные ID конфликтуют либо она нарушает включение/границы слотов
- **THEN** сервер возвращает 500 без stack trace и секретов

#### Scenario: Fragment conflicts with framework or shell

- **WHEN** один фрагмент содержит зарезервированный ID, включая `islands-payload`, либо ID оболочки
- **THEN** этот слот заменяется fallback с диагностикой, payload остаётся единственным и соседние острова продолжают гидратироваться

#### Scenario: Cross-slot identity collision

- **WHEN** два фрагмента используют одинаковый DOM ID
- **THEN** сохраняется фрагмент первого слота в порядке конфигурации, последующий конфликтующий слот получает fallback, а результат не зависит от порядка завершения fetch

#### Scenario: Parser changes slot ownership

- **WHEN** HTML parser переносит wrapper за границу его слота или делает roots вложенными
- **THEN** атрибутируемый некорректный слот отклоняется; если источник нарушения нельзя однозначно определить, сервер возвращает безопасный 500

### Requirement: Bounded isolated fragment failures

Система SHALL ограничивать ожидание каждого слота настраиваемым deadline (1500 мс по умолчанию), включающим ожидание admission/cache, manifest и render, отменять просроченные запросы и показывать fallback только отказавшего слота. Ответ manifest SHALL быть ограничен 64 KiB, render response — 1 MiB по умолчанию, включая потоковые ответы без Content-Length. Поздний ответ SHALL NOT менять сформированный документ.

#### Scenario: Timeout or invalid response

- **WHEN** один сервис недоступен, превышает deadline/лимит, возвращает ошибку либо невалидный ответ
- **THEN** страница имеет статус 200, fallback этого слота и содержимое остальных успешных слотов; поздний ответ игнорируется

#### Scenario: Client disconnect

- **WHEN** клиент закрывает соединение до завершения композиции
- **THEN** его незавершённые исходящие запросы и чтение тела отменяются; разделяемая загрузка manifest сохраняется только при наличии других ожидающих клиентов

#### Scenario: Slow or oversized streamed body

- **WHEN** headers получены вовремя, но тело задерживается за общий deadline либо поток без Content-Length превышает byte limit
- **THEN** чтение тела прекращается и слот получает fallback, не дожидаясь завершения upstream body

### Requirement: Health and readiness

Система SHALL предоставлять `/healthz` для проверки процесса и `/readyz` для проверки локальной готовности. Готовность модуля SHALL учитывать identity, полный deployment inventory, regular files, контрольные суммы и вызываемый server renderer каждого опубликованного релиза. Система SHALL предоставлять отдельную готовность релиза по `/releases/:releaseId/readyz`. Готовность SHALL проверяться до admission и повторно с конечным настраиваемым интервалом; просроченный результат SHALL NOT выдаваться как подтверждение готовности без ограниченной по времени перепроверки.

#### Scenario: Remote unavailable

- **WHEN** локальная конфигурация корректна, но один удалённый модуль недоступен
- **THEN** readiness host остаётся успешной, а отказ модуля обрабатывается на уровне слота

#### Scenario: Invalid initial configuration

- **WHEN** при запуске нет корректного registry или обязательных локальных артефактов
- **THEN** readiness возвращает неуспешный статус

#### Scenario: Missing transitive asset or invalid renderer

- **WHEN** у опубликованного релиза отсутствует shared/async chunk, checksum не совпадает, вместо файла находится директория либо renderer не является вызываемым
- **THEN** readiness этого релиза и общая readiness модуля возвращают 503; повреждённый релиз не обслуживает render, исправные опубликованные релизы продолжают обслуживаться

#### Scenario: Unknown and valid releases

- **WHEN** запрашивается readiness неизвестного/неопубликованного либо полностью проверенного релиза
- **THEN** endpoint возвращает соответственно 404 либо 200; module readiness успешна только при наличии хотя бы одного исправного опубликованного релиза и отсутствии повреждённых опубликованных релизов

#### Scenario: Artifact corruption after admission

- **WHEN** обязательный файл изменён или удалён после успешного admission
- **THEN** следующая integrity-проверка не позже настроенного интервала инвалидирует готовность и доступ к повреждённому релизу, сохраняя liveness процесса
